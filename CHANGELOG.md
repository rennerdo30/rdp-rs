# Changelog

## Unreleased

## 0.1.0-beta.15

- **Caps Lock no longer gets stuck on.** Tabbing back into a session no longer turns the remote Caps Lock on, and Caps Lock (on a Japanese keyboard the 英数 key) switches it on and off each time. When a session connects or gets the keyboard back, the remote Caps, Num and Scroll Lock are set to this PC's. With **Automatic** or **Translate** typing, this PC's Caps Lock already decides the case, so the remote one stays off (RDP-91).

## 0.1.0-beta.14

- **Smaller recordings you can seek in.** Session recordings no longer cost the same per second whatever is on screen: a still desktop now takes about 2 MB a minute at 1080p instead of about 15, while text stays sharp. Recordings also have a keyframe every 2 seconds, so jumping or scrubbing in a player shows the right moment instead of the first frame (RDP-20).
- **Imports in their own group.** Connections imported from mRemoteNG or MobaXterm land in one group named after the app (**mRemoteNG**, **MobaXterm**), with their folders inside it, instead of among your own connections at the top level. RDCMan's file already became a group of its own (RDP-89).

## 0.1.0-beta.13

- **Imports found on this PC.** When MobaXterm's (`%APPDATA%\MobaXterm\MobaXterm.ini`) or mRemoteNG's (`%APPDATA%\mRemoteNG\confCons.xml`) connections are where those apps keep them, Settings shows a one-click **Import** for each, and the first start offers **Import from MobaXterm**. The file dialog also lists MobaXterm's configuration exports (`.mobaconf`) (RDP-89).

## 0.1.0-beta.12

- **Import from MobaXterm.** **Import…** also reads `MobaXterm.ini` and exported `.mxtsessions` files: folders become groups, RDP sessions keep host, port, user and RD Gateway, SSH sessions become SSH connections with their key file, and an SSH gateway becomes the jump host. Other session types are skipped and counted; MobaXterm keeps passwords apart, so none come over. SSH connections can now have a jump host too (`ssh -J`) (RDP-89).
- **SSH connections.** The editor has a **Type**: **Remote Desktop** or **SSH**. An SSH connection (host, port 22, user, optional key file) opens Windows' own OpenSSH client in a Windows Terminal tab, or a console without Windows Terminal; it has an **SSH** tag in the sidebar, Home and Ctrl+K. No password is saved for it: ssh asks, or uses the key or the OpenSSH agent. The mRemoteNG import now keeps SSH1 and SSH2 connections instead of skipping them (RDP-87).
- **RDP through an SSH jump host.** **Jump host** (`user@host:port`) and **Key file** on the sign-in card: Remora signs in to the jump host with the key file, the OpenSSH agent or Pageant (never a password) and runs the Remote Desktop connection in an SSH tunnel to the PC. The jump host's key is trusted on first use like a certificate (or from OpenSSH's known_hosts); the connecting and error screens name the jump host step. On the command line: `--jump`, `--jump-key` and `--expect-jump-fingerprint` (RDP-88).
- **Checked live.** `scripts/ssh-vm-test.py` runs both in a throwaway lab VM against Windows' own OpenSSH Server: a Remote Desktop session through the jump host with a pinned key (a wrong key is refused before any sign-in), and `remora --ssh` (new: an SSH connection from the command line) starting ssh.exe in Windows Terminal, which passes `-p`, `-l`, `-i` and `--` through unchanged and signs in with the key (RDP-87, RDP-88).

## 0.1.0-beta.11

- **On crates.io.** `cargo install remora-client --version 0.1.0-beta.11` builds and installs `remora` (Windows). The protocol library is published as `rdp-proto` (RDP-86).
- **FIPS level for legacy RDP security.** Old servers set to the FIPS encryption level (Standard RDP Security with Triple DES and HMAC-SHA-1, no TLS) can now be reached with **Allow legacy RDP security (weak)**; before, they were refused. Checked against Windows' own server at level 4 in a 90-second drawing session, and the RC4 levels again (RDP-84).
- **Shadowing from the app.** A connection's **Advanced** page has **Sessions…** under **Other sessions** (also **Sessions on …** in the command palette): the server's signed-in sessions with **Watch** and **Control**, and **Ask the user first** on by default. **Join a shared desktop** in the command palette opens a Windows Desktop Sharing invitation file. The command line flags stay; not yet tried against a real server (RDP-85).
- **Ready for crates.io.** The packages are now `rdp-proto` (the protocol library, still `rdp` in code) and `remora-client` (the app, still `remora.exe`), since `rdp` and `remora` on crates.io belong to other projects; `remora-link` and `remora-update` are published with them. A manual workflow uploads them after a stable release. Not published yet: `ffwd-render` has to be on crates.io first (RDP-86).

## 0.1.0-beta.10

- **Import connections from mRemoteNG and Remote Desktop Connection Manager.** **Import connections** (Settings, Backup, and the first start) now also reads mRemoteNG's `confCons.xml` and RDCMan's `.rdg` files, next to Remora backups; the format is told from the content. Groups, inherited settings, gateway, display size and sharing come over. mRemoteNG passwords are read with its default master password or the one you type (also fully encrypted files); RDCMan passwords only on the PC and Windows account that saved them. Passwords are kept only in the vault; the result says what could not be imported and why (RDP-80).
- **Serial and parallel ports.** Share this PC's COM and LPT ports with the session, one switch per port, off by default, per connection or live from the side panel. Checked against Windows' own server: a program in the session opens the port, sets the baud rate, writes and reads back (RDP-74, RDP-82).
- **Cameras.** Share this PC's cameras with the session, all or one, off by default and switchable live; a camera turns on only while an app in the session uses it. Checked against Windows' own server: an app in the session takes a photo from a shared camera (RDP-75, RDP-83).
- **Legacy RDP security, for old servers.** Servers that offer only Standard RDP Security (RC4 at 40, 56 or 128 bits, no TLS) can be reached when **Allow legacy RDP security (weak)** is on for that connection (Advanced page, or `--legacy-security`). It is never chosen on its own: TLS is always tried first, and the server's key is checked like a certificate. Checked against Windows' own server at all three encryption levels, with key updates in long sessions. FIPS-level servers are not supported (RDP-73).
- **RD Gateway over RPC.** Gateways that do not offer the HTTP transport are reached over RPC over HTTP, automatically, or always with **Gateway over RPC** (`--gateway-rpc`); errors name the step that failed. Not yet tried against a real gateway (RDP-78, RDP-81).
- **UDP transport (opt-in).** With **UDP transport** on (Advanced page, or `--udp`), the session's graphics, sound and input channels run over reliable UDP with TLS when the server offers it; any UDP failure keeps or returns the session to TCP, and the statistics show which transport is in use. The fallback is checked against Windows' own server; UDP itself not yet (RDP-79).
- **Video redirection (opt-in).** With GFX, **Video redirection** offers Windows' Video Optimized Remoting: video the server detects arrives as its own H.264 stream, decoded here and shown in place. Windows 11 opens the channels but has not redirected a video in tests yet (RDP-76).
- **Shadowing and shared desktops.** `remora <host> --list-sessions` and `--shadow ID [--control] [--no-consent-prompt]` watch or control another user's session on a Windows server, like `mstsc /shadow`; `--invitation FILE` joins a Windows Desktop Sharing invitation, and the command palette can request control. Command line only so far, and not yet tried against a server (RDP-77).

## 0.1.0-beta.9

- **Helper picture (experimental).** **Use the helper picture** on the Session page lets the server helper capture the session's picture itself and send it to Remora in place of RDP's picture. Small changes (typing, menus, a cursor in text: up to 512×512 pixels) go as exact, LZ4-compressed tiles without any video encoder; larger ones are encoded as H.264 on the server's GPU (or in software without one), with only the changed regions converted and at most two pictures in flight. On a LAN server with an AMD GPU the latency meter measured 15 ms to the picture against RDP's 27–30 ms there (helper 1.9 ms, transfer 1.8, decoding 1.7, painting 0.9). **Back to the RDP picture**, or the stream stopping (the lock screen, a resolution change), returns to the normal picture. Still experimental: one monitor only, and tiles are not yet made smaller on slow links (RDP-67, RDP-71; helper protocol 1.2, `StreamStart`).
- **Faster H.264 decoding.** Remora kept splitting every decoded H.264 picture into separate colour planes, byte by byte; at 3688×1984 that cost 3 ms per picture, twice per AVC444 frame. Pictures now stay in the decoder's layout, and the decoder's output and the pictures' memory are reused instead of fresh 11 MB allocations for every picture: decoding takes 3.5 ms per frame instead of 10.9 ms at that size (1.1 instead of 2.1 ms at 1280×800). A lab test that slows decoding on purpose showed every millisecond of it in the picture's latency. Found with the new latency meter: on a LAN server it measured 34 ms, a third of it Remora's own decoding (RDP-67).
- **Latency meter.** **Measure latency** on the side panel's Session page (with a paired server helper) times how long a change on the server takes to reach Remora's picture: the helper paints a small square in a colour Remora names, 20 times, and Remora times each change from asking to the decoded frame. It shows the median, the range and the helper channel's own round trip. The same meter will compare the server's RDP picture with a helper stream (RDP-67; helper protocol 1.2, `LatencyMark`).
- **Keyboard: Remote is the default.** Keys go to the session as keys and its layout decides the characters, which every program reads. Connections saved with the old default, Automatic, switch once; Translate stays. Remora's own text fields also take typed text that comes without a key (another RDP client's Unicode input, the touch keyboard) (RDP-68).
- **Compression no longer breaks sessions.** With RDP 5.0 or RDP 6.1 compression the connection failed within a second ("copy-offset … outside the history"), and RDP 6.1 garbled the picture before that. Two decoder faults, both fixed: RDP 5.0 matches may reach "behind" the start of the history into its end (it is a ring), and RDP 6.1 keeps its level-1 history when it starts over at the front instead of clearing it. Virtual channel data is also no longer offered for compression, as with FreeRDP. A new live test holds each of the four types for 45 s against Windows' own server (RDP-69).

- **Typing reaches every program.** With translated typing (Automatic), Remora sent text as Unicode, which programs that read keys ignore: games, VM consoles, winit apps such as Remora itself and ffwd. When the session's layout is known, Remora now types each character with that layout's key and Shift or AltGr; only characters it cannot type still go as text. The server helper reports the layout (protocol 1.2, `KeyboardLayout`); without it, name it under **Server keyboard layout** on the editor's Experience page (RDP-68).
- **A PC the helper already trusts is not asked about again on the server.** When Remora asked to compare codes (for example after its pins were reset) the helper showed its dialog too, held every transfer while it waited, and closed the connection after 5 minutes unanswered. Found by the new live helper test (RDP-64).
- **`remora-agent capture-probe`** measures whether the helper can capture the session's picture itself, how fast, and which video encoders the server has (RDP-67, first step). It then benchmarks the server's hardware encoders on the captured picture, scrolling at 60 fps: GPU conversion, H.264, HEVC and AV1 in low-latency mode, with latency, frame sizes and bitrate per encoder (second step; the CPU path stands in when there is no GPU).

- **Zip folders and e-mail attachments paste on the server.** Files that exist on this PC only as data (inside a zip folder, an Outlook attachment) can be copied here and pasted in the session; files copied on one server can be pasted on another (RDP-63).
- **The command line checks server certificates.** `remora <host> --screenshot` and `--record` accept a known certificate, ask about a new or changed one on a console (and remember it), and refuse it without a console; scripts pass `--expect-fingerprint` (RDP-54).

- **The setup installs the server helper too.** Choose Remora, the server helper, or both; the helper is preselected on a Windows Server or inside a remote session, set up for your user and started. Silent installs take `/COMPONENTS=helper` or `/COMPONENTS=app,helper`; updates keep what is installed, and uninstalling removes the helper's task and Send To shortcut too (RDP-65).

- **Send folders through the server helper.** Drop a folder onto the session, or use **Send To > Send to my PC (Remora)** on a folder on the server: it goes whole, with its subfolders, and arrives as one folder (`name (2)` when that name is taken). Remora asks once per folder and shows one progress row; every file keeps resume and integrity checks. Needs the helper of this version on the server (RDP-64).

- **Copy images, and big files and folders, through the clipboard.** Images now copy both ways (they were announced as text before, so nothing arrived). Files and folders copied on the server are on this PC's clipboard at once and are fetched only when you paste: Explorer copies them straight from the server with its own progress window, like Microsoft's client, with no 4 GB limit and no download before the paste. Files and folders copied on this PC paste on the server again: Remora now announces the file contents with the file list, as Windows does (without it the server's paste copied nothing). Several sessions can pass text and images from one server to another. Tested end to end against Windows' own Remote Desktop server, both ways, with a 4.3 GB file (RDP-62, RDP-63).

- **Remora updates the server helper.** When a paired helper is older than Remora, a card at the picture's top right asks **Update the helper on this server?** (**Update**, **Later**, **Don't ask again** for that server), and the side panel's Session page offers **Update helper to …** (RDP-66). Remora downloads the helper of its own version from the GitHub release, checks it against the release's checksums, and sends it over the encrypted helper connection. The helper accepts it only from a PC confirmed on the server, checks it again, replaces itself and reconnects. Helpers older than this version are replaced by hand once (RDP-61).

- **A hint on servers without the helper.** When a desktop session has run for 15 seconds and no Remora helper showed up, a small card at the picture's top right says what the helper adds (file transfer, links on this PC, faster graphics settings). **How to install** opens the guide, **Later** hides it for this connection, and **Don't show again** hides it for that server (RDP-60).
- **The server helper tunes the server's graphics.** With a paired helper (protocol 1.2), the side panel's Session page shows what limits the picture on the server: the 30 fps cap Windows puts on remote sessions, whether H.264 is preferred over ClearCodec, and whether the GPU encodes. **Improve** sets 60 fps, H.264/AVC 444 and hardware encoding. The change needs one administrator prompt on the server, confirmed there. Restart the server for the frame rate; reconnect for H.264. **Restore defaults** removes the settings again. Helpers before 1.2 show nothing new (RDP-59).

- **Less work for the server's encoder with GFX.** Remora now offers the server the normal 100 MB graphics cache, as Microsoft's client does, instead of the small 16 MB one. A 4K desktop is about 30 MB, so with the small cache the server had to encode again what it had already sent, for example when scrolling or switching windows.
- **GFX is the default.** New connections use the graphics pipeline with H.264. Existing connections saved with the old default, Bitmaps, switch once; choose **Bitmaps** again on the editor's Advanced page or in the side panel if you want them. When a server's graphics fail, the tab reconnects once with plain bitmaps on its own.
- **A statistics overlay.** **Show statistics** shows a small box over the picture. The switch is on the side panel's Session page, and the toolbar's ⋯ menu and the command palette have it too. It is updated once a second and lists:
  - the round trip, from a ping to the server once a second, and what the server's network detection found;
  - the input-to-picture latency, from a key or click to the next screen change (average and worst);
  - GFX frames per second with codec and decoding time, or Bitmap, and Remora's own update-to-screen time;
  - updates and repaints per second, and the traffic in and out.

  Remora remembers whether it is on (RDP-56).

## 0.1.0-beta.8

- **Reconnect no longer freezes Remora.** Reconnecting a tab that was still connected (for example after switching its Graphics option to GFX) hung the window for good, "not responding", while the new connection ran on behind it. The old connection's "disconnected" was taken for the new connection's end, and the window then waited for the new connection to finish. Each connection's events are now told apart, and the window never waits for a connection to end (RDP-55).
- **The programs start on a clean Windows.** Remora, the server helper and Remora Host needed the Visual C++ runtime (`vcruntime140.dll`), which a fresh install, Server Core or Windows Sandbox does not have: they did not start there at all. The runtime is now built in.
- **Remora Host:** a GDI screen capture when Desktop Duplication is not available (remote sessions such as Windows Sandbox, no GPU), chosen automatically (also when Desktop Duplication gives no usable picture, black frames or none at all, as on the Venera virtio-gpu driver in QEMU guests) or with `--capture gdi`; `set-password --password-file` for scripted tests. `scripts/host-sandbox-test.ps1` runs the server in Windows Sandbox and `scripts/host-vm-test.ps1` in a throwaway clone of the renner.dev OS lab's Windows VM, and both connect Remora to it and check that the picture is not blank.
- **`remora --expect-fingerprint SHA256`** accepts only that server certificate in the command-line mode.

## 0.1.0-beta.7

- **Typing comes out right with another server layout, and Windows keys go where they should.** Automatic keyboard now sends what you type as the characters your layout makes from the start: a server keeps its own layout when it lacks yours (or the session already existed), and RDP does not tell Remora, so a Japanese keyboard typed nonsense into a German session. Shortcuts, navigation and function keys stay keys; **Remote** still sends every key as a key. **Windows key combinations** now go to the session whenever it has the keyboard by default (Win+R, Alt+Tab), and a Windows key that stays on this PC is no longer sent to the session as well (both Start menus opened). The Windows key never reached the session before: winit registered raw keyboard input for Remora's window, and Windows then skips the process's own keyboard hook while its window has the focus. Remora no longer registers raw input, and like mstsc it hooks the keyboard afresh whenever the session takes it. Keys that type nothing here, such as the Japanese 半角/全角 IME key that the IME also sends when Remora gets the focus back, are no longer sent as keys, so they cannot type the remote layout's character (`^` on German).
- **Experimental: Remora Host, our own RDP server (`remora-host`).** It serves a Windows desktop to Remora or another RDP client over TLS with a self-signed certificate and its own password (Argon2id hash, rate-limited): uncompressed bitmap updates of the changed tiles, keyboard and mouse, one client at a time on port 3390. `remora-host run --demo` serves an animated test pattern instead, on any platform, and shows the input it receives. No NLA, clipboard, audio or multi-monitor yet; not part of the release packages. See `crates/remora-host/README.md` and `docs/HOST.md`.

## 0.1.0-beta.6

- **In-app updates start again after an update.** A Remora that the setup had started (after the previous update) failed to start the next setup with "could not start the setup: The request is not supported (os error 50)": it handed its stale standard handles on to the setup. ## 0.1.0-beta.5

- **New: the Remora server helper, `remora-agent.exe`** (a separate download in this release, and in the zip). Run it on a Windows server or PC you connect to and `remora-agent install` starts it for your user at every logon and reconnect (a scheduled task; no admin rights). It shows a tray icon (grey: waiting for Remora, amber: a pairing waits for you, green: connected) with received files, the helper's fingerprint, paired PCs, **Only paired PCs may connect**, the log and Quit. Paired with Remora, it reports the session's state, sends links you click on the server to your PC's browser, and moves files both ways with resume after a reconnect (**Send To > Send to my PC (Remora)** on the server; drop files onto Remora to send them there). Everything between the two is encrypted on top of RDP's own TLS. To update it, choose **Quit helper** in its tray menu, replace the exe and start it again; pairings are kept. See `crates/remora-agent/README.md` and the user guide.
- **The server helper in Remora (RDP-42, RDP-43, RDP-44).** With `remora-agent` running on the server, Remora asks once to pair it (compare a six-digit code; a changed key is a warning whose default is Don't pair), then shows the server's state on the side panel's Session page: locked or not, idle time, CPU and memory. Per connection (editor, Sharing page), and off until you switch them on: **Open links on this PC** (a card asks for each http/https link; **Always for this server** stops asking), **Receive files from the server** (a card asks for each file; saved into `Downloads\Remora` or your folder, never over an existing file, with the Mark-of-the-Web) and **Send files to the server** (drop files onto the session, or **Send files to…**). Transfers are listed on the Sharing page with progress, speed and cancel, and resume after a reconnect. Without a helper nothing of this shows.
- **The server helper's security is hardened before its first release.** The helper now remembers your PC as Remora remembers it and exchanges files and links only with a PC it knows; pairing stops after repeated unanswered or stalled attempts (**Retry pairing** allows it again); fingerprints can be pinned on both sides instead of comparing the code in the remote picture, and the helper's **pinned clients only** mode (`remora-agent strict on`, automatic after `trust-client`, or the `PinnedClientsOnly` policy) refuses unknown PCs without a window to click; oversized channel data, unsafe file names and shortcut and theme types are refused or neutralized; received files are never stored without the Mark-of-the-Web, so a download folder must be on an NTFS drive; and file transfer runs off the session thread.
- **The session toolbar hides again.** It stayed over the picture while the side panel was docked (the default until now) and until you clicked into the session. A docked panel no longer keeps it up, and a session that connects on screen takes the keyboard at once, so the toolbar shows only on the top edge, with Alt held, or while the floating panel is open.
- **The session panel folds to a strip and floats.** By default the side panel is now a slim strip of page icons (with tooltips) at the picture's right edge; an icon, the toolbar's Panel button or **Ctrl+Alt+P** (also from inside the session) opens the panel floating over the picture, so the remote desktop is not resized. A click on the picture or **Esc** closes it, and neither reaches the session. The pin in its header docks it beside the picture as before; Remora remembers the choice, and the palette has **Pin/Unpin session panel**. Full screen has no strip.
- **No more repeated reconnects on some servers.** RemoteFX/NSCodec surface commands and drawing orders, new in 0.1.0-beta.2, are off again by default: a Windows server failed its picture encoding with them (0x112F) or dropped the connection after the window's size was applied, which looked like five connection timeouts before compatible mode took over. Remora draws as in 0.1.0-beta.1 again; `--surface-commands` and `--drawing-orders` turn them on for testing.
- **The microphone works.** Remora never told the server at logon that it can record audio (INFO_AUDIOCAPTURE), so the server never opened the microphone channel and the remote PC reported no microphone, whether **Microphone** was switched on before or after connecting. It now does, and the switch works live in a running session.

## 0.1.0-beta.4

- **A sidebar that folds and resizes, and a resizable side panel.** The menu button at the sidebar's top left, **Ctrl+B** or **Collapse sidebar** in the palette folds the sidebar to a narrow rail of icons with each connection's initials, live dot and a tooltip. Drag the sidebar's right edge (200 to 480 px; narrower folds it) and the session side panel's left edge (280 to 560 px); a double-click on an edge resets it. A fitted session is resized once when the drag ends. The fold and both widths are remembered.

Now **Opens** decides only what Connect does (the desktop by default), and the programs are listed under the connection in the sidebar, the editor and the palette whatever it opens; each starts its own RemoteApp window.

## 0.1.0-beta.3

- **Servers whose picture encoding failed now connect.** Some Windows servers gave up about a second after logon with error 0x112F ("the server's graphics subsystem failed"). Remora now reconnects such a session once in compatible mode, without RemoteFX surface commands and drawing orders, as 0.1.0-beta.1 drew the screen, and keeps that mode for the tab's later reconnects.
- **Closer to the specification:** Remora offers a receive buffer large enough for a whole frame at the desktop size (it was 8 MB), and promises the server its cached-bitmap list only when it sends one.
- **Clearer errors:** the server's graphics and monitor errors (0x112C to 0x1136) are named instead of "server rejected a client PDU".
- **Open log** on the error screen opens Explorer with `remora.log` selected, in front of Remora.

## 0.1.0-beta.2

- **rdpc is now Remora.** The app has a new name and a new logo: a remora fish whose body is a screen. The executable is `remora.exe`, the setup is `remora-<version>-setup.exe`, and it installs to `%LOCALAPPDATA%\Programs\Remora` with a Start menu and Installed apps entry named Remora. The protocol library (`rdp`) and the repository (`rdp-rs`) keep their names.
  - **Updating from rdpc 0.1.0-beta.1 needs nothing from you:** rdpc's updater finds the new release as before, and the setup moves the install: it waits for rdpc to close, installs Remora, removes rdpc's program folder, Start menu shortcut and Installed apps entry, and starts Remora.
  - **Your data stays where it is:** saved connections, the vault, settings, known hosts and logs remain in the `rdp-rs` folders under `%APPDATA%` and `%LOCALAPPDATA%`. The diagnostic log is now `remora.log`, and new recordings go to `Videos\Remora` (earlier ones stay in `Videos\rdpc`).
  - A taskbar button pinned to rdpc stops working after the move; pin Remora again.
- **A website and a user guide.** [remora.renner.dev](https://remora.renner.dev) shows Remora with real screenshots, and `docs/` has a getting-started page, a user guide, every keyboard shortcut, troubleshooting for each error screen, and what is stored where.
- **A new look.** Every screen is redesigned: dark and light themes (following Windows or chosen in Settings), a new icon set and calmer layouts.
  - **Home** shows running sessions with live thumbnails, favourites and recent PCs, with quick connect for a name, an address or `user@host:port`.
  - **Ctrl+K command palette** finds sessions, connections, RemoteApp programs, groups and commands; **Ctrl+Alt+K** opens it inside a session.
  - **Connecting** shows each step of the connection. A failure says why, where it stopped and what to try; an ended session says why it ended and offers to reconnect.
  - A floating session toolbar replaces the old bar in full screen.
- **Monitors:** pick any subset of this PC's monitors per connection on a map in the editor. The session gets one borderless window per chosen monitor; the others stay free.
- **RemoteApp:** publish programs per connection and launch them from the sidebar, Home or the palette. Each remote window becomes its own local window with a taskbar button.
- **Sign in with Windows:** Kerberos through Windows (NTLM as fallback), and single sign-on with an empty user name. It's a switch in the editor, inherited like the sign-in.
- **Keyboard:** Remora tells the server this PC's keyboard layout at connect. A new Keyboard option translates typing for a server with a different layout. Text without a key (touch keyboard, emoji panel) is sent as Unicode.
- **Touch and pen** (MS-RDPEI): multi-touch, and pen with pressure and tilt.
- **Picture:** H.264 AVC444 (experimental, with AVC420 as before), drawing orders with glyph, brush and offscreen caches, a persistent bitmap cache per server (at most 100 MB), and RemoteFX and NSCodec surface bits for RDP 7 servers.
- **Sound:** AAC, MP3 and ADPCM playback besides PCM.
- **Connection:** server redirection (session broker and load balancing) while connecting and during a session; network auto-detect with a "Detect automatically" speed, whose results appear in the session panel; the full licensing exchange, with licenses kept in `%LOCALAPPDATA%\rdp-rs\licenses`.

Not yet: UDP transport, RD Gateway over RPC/HTTP, legacy RDP security, serial ports, USB, cameras, plug and play devices, video redirection and shadowing. Most of what is new has been tested against the specifications and in unit tests, not yet against every kind of Windows server. The setup is still not code-signed, so Windows SmartScreen warns on the first run.

## 0.1.0-beta.1

The first beta of rdp-rs: an RDP client written from the Microsoft Open
Specifications, with its own protocol stack (no FreeRDP, no mstsc). Expect
rough edges, and please report them.

- **Connection:** X.224 negotiation (TLS, NLA, NLA with early user authorization), CredSSP v6 with NTLMv2, MCS/GCC, licensing, capability exchange, finalization and reactivation. **RD Gateway** (MS-TSGU HTTP transport over WebSocket, NTLM).
- **Security:** the server certificate is checked before any password is sent: trust on first use, a warning when it changes (`known_hosts.json`). The same check covers the gateway.
- **Display:** fast-path and slow-path bitmap updates (planar, interleaved RLE), the default for the lowest latency. Optional **graphics pipeline** (RDPGFX): ZGFX, ClearCodec, NSCodec, RemoteFX Progressive and H.264 (AVC420, Windows Media Foundation), still experimental. Fit-to-window and live scaling via Display Control; full screen with a hiding bar (Ctrl+Alt+Break).
- **Quality:** connection speed presets (LAN to modem), colour depth (32/24/16/15-bit), desktop experience switches (wallpaper, font smoothing, composition, animations, …) and bulk compression (RDP 5.0 to 6.1).
- **Input:** keyboard with this PC's layout, mouse, Ctrl+Alt+Del. Windows key combinations (Win, Alt+Tab, …) go to the remote session on this PC, remotely, or in full screen only.
- **Sharing,** off until you enable it and switchable live without reconnecting:
  - clipboard (text and files, both ways);
  - shared folders (with a folder picker);
  - printers (Easy Print, no drivers on the server);
  - smart cards;
  - sound, on the output device you choose;
  - microphone, from the device you choose.
- **Sessions:** a tab per session, a quick panel (Sharing, Display, Quality, Session), auto-reconnect with the server's cookie and heartbeat, and recording to MP4.
- **Connections:** an editor in sections (General, Display, Experience, Sharing, Advanced); groups with inheritance and Connect all; an encrypted vault (Argon2id + XChaCha20-Poly1305) for saved passwords with a master password, idle auto-lock, "unlock on this PC" (DPAPI) and encrypted export/import.
- **App:** Settings (security, backup, updates, diagnostic log); asks before quitting with open sessions.
- **Windows setup:** a per-user installer (no admin rights) and a portable zip. Installed copies update themselves from GitHub releases (Automatic, Stable or Beta channel); every download is checked against the release's `SHA256SUMS.txt`.

Not yet: Kerberos, AVC444, multi-monitor, drawing orders, UDP transport, RDS licensing and legacy RDP security. The setup is not code-signed, so Windows SmartScreen warns on the first run.
